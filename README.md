## Sample Source File

**`sample.c`** contains five functions, each with at least one deliberate defect:

```c
/* sample.c - demonstration file for Polyspace analysis */
#include <stdlib.h>
#include <string.h>   /* intentionally unused */

/* Potential division by zero */
int divide(int a, int b) {
    return a / b;
}

/* Potential null pointer dereference */
void process(int *ptr) {
    *ptr = 42;
}

/* Potential array out-of-bounds */
void fill_array(void) {
    int arr[5];
    for (int i = 0; i <= 5; i++) {   /* off-by-one: writes arr[5] */
        arr[i] = i;
    }
}

/* Potential memory leak */
void memory_leak(void) {
    int *p = (int *)malloc(sizeof(int) * 10);
    /* p is never freed */
    p[0] = 1;
}

int main(void) {
    int x = divide(10, 0);   /* b=0 → division by zero */
    process(NULL);            /* NULL pointer dereference */
    fill_array();
    memory_leak();
    return 0;
}
```

### Intentional defects summary

| Function | Defect |
|----------|--------|
| `divide()` | Division by zero (`b = 0` at call site) |
| `process()` | Null pointer dereference (`NULL` passed from `main`) |
| `fill_array()` | Array out of bounds (loop bound `<= 5` on a 5-element array) |
| `memory_leak()` | Memory leak (`malloc` result never freed) |
| `main()` | Calls all of the above; `x` is assigned but never read |

## Checkers Configuration

**`checkers.xml`** tells Polyspace which rule families to check. The following standards are enabled:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- DO NOT EDIT THIS FILE: Some changes can lead to a crash of Polyspace products -->
<polyspace_checkers_selection
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:noNamespaceSchemaLocation="selection_schema.xsd"
    revision="2.0">
  <standard name="Bug Finder Findings" state="on"/>
  <standard name="MISRA C:2012"        state="on"/>
  <standard name="MISRA C:2023"        state="off"/>
  <standard name="MISRA C++:2008"      state="off"/>
  <standard name="MISRA C++:2023"      state="off"/>
  <standard name="SEI CERT C"          state="on"/>
  <standard name="SEI CERT C++"        state="off"/>
  <standard name="ISO/IEC TS 17961"    state="off"/>
  <standard name="AUTOSAR C++14"       state="off"/>
  <standard name="CWE"                 state="on"/>
</polyspace_checkers_selection>
```

| Standard | Enabled | Purpose |
|----------|---------|---------|
| Bug Finder Findings | Yes | Runtime defects (null deref, div-by-zero, memory leak, OOB, …) |
| MISRA C:2012 | Yes | Automotive/embedded C coding rules |
| SEI CERT C | Yes | Security-focused C coding guidelines |
| CWE | Yes | Common Weakness Enumeration mapping |

To customise checkers, either edit `checkers.xml` directly or launch the interactive UI:

```powershell
polyspace-checkers-selection.exe -checkers-selection-file-readonly "C:\demo\polyspace_agentic_toolkit\checkers.xml"
```

## Running the Analysis

Run **Polyspace as You Code** from PowerShell:

```powershell
polyspace-as-you-code.exe `
    -sources          "C:\demo\polyspace_agentic_toolkit\sample.c" `
    -checkers-activation-file "C:\demo\polyspace_agentic_toolkit\checkers.xml" `
    -results-dir      "C:\demo\polyspace_agentic_toolkit\results"
```

### Command-line options explained

| Option | Value | Description |
|--------|-------|-------------|
| `-sources` | `sample.c` | C/C++ source file(s) to analyse |
| `-checkers-activation-file` | `checkers.xml` | Which rule families and checkers to enable |
| `-results-dir` | `results\` | Output folder (created automatically if absent) |

**Optional flags** (not used here, but useful):

| Option | Description |
|--------|-------------|
| `-options-file <build_opts.txt>` | Pass compiler flags, include paths, defines |
| `-import-comments <baseline\>` | Suppress findings already reviewed in a previous run |
| `-author <name>` | Tag results with a reviewer name |

**Expected runtime:** a few seconds for a small standalone file.  
**No output to the console** means success. Check `results\polyspace_err.log` if something goes wrong.

## Exporting Results to SARIF

The native `.payc` file can be opened in the Polyspace IDE or VS Code extension. To get a human-readable / CI-friendly JSON export:

```powershell
polyspace-results-export.exe `
    -format      json-sarif `
    -results-dir "C:\demo\polyspace_agentic_toolkit\results" `
    -output-name "C:\demo\polyspace_agentic_toolkit\results\results.sarif"
```

Expected output:

```
Generated: C:\demo\polyspace_agentic_toolkit\results\results.sarif
```

The SARIF file follows the [SARIF 2.1.0 standard](https://docs.oasis-open.org/sarif/sarif/v2.1.0/) and can be consumed by:

- VS Code (SARIF Viewer extension)
- GitHub Advanced Security (`upload-sarif` action)
- Azure DevOps / Jenkins pipelines
- Any SARIF-aware static analysis dashboard
